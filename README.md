# URC_Remote1C

[![Infostart](https://infostart.ru/bitrix/templates/sandbox_empty/assets/tpl/abo/img/logo.svg)](https://infostart.ru/1c/articles/2814517/)

**Публикация на Infostart:** [URC_Remote1C — расширение для обмена между базами 1С](https://infostart.ru/1c/articles/2814517/)

Расширение 1С для синхронного обмена между информационными базами через HTTP. Позволяет выполнять запросы, читать реквизиты и объекты, создавать и записывать справочники и документы, работать с ХранилищеЗначения и вызывать заранее зарегистрированные серверные процедуры.

**Версия:** 0.5.0 · **Протокол:** Remote1C/1.0

## Возможности

- Проверка соединения и возможностей удалённой базы.
- Запросы с именованными параметрами и переносимыми ссылками.
- Чтение реквизитов, табличных частей и снимков объектов.
- Создание и запись объектов, проведение и отмена проведения документов.
- Контроль конкурентных изменений при записи.
- Ленивое чтение ХранилищеЗначения, явные операции Set, Clear и Copy.
- Именованные процедуры из локального реестра сервера.
- Формы настройки и диагностики, журнал событий Remote1C.*.

Это синхронный API: расписание вызовов, сопоставление данных и обработку результата определяет прикладной код. Автоматическая очередь и расписание обмена в расширение не входят.

Для используемых методов системного хранилища требуется платформа **8.3.26 или новее**. В метаданных указан режим совместимости расширения `Version8_3_21`; эта поставка выгружена на **8.3.27.2214**. Применимость и права проверяйте в своей конфигурации. Примеры с Номенклатурой и документами требуют соответствующих метаданных.

Рабочая версия платформы проекта — **8.3.27.2214**. Требуются управляемое приложение, поддержка расширений и веб-публикация HTTP-сервиса `URC_API`. Веб-сервер и его веб-расширение должны соответствовать выбранному релизу 1С; доступ к публикации нужен с сервера клиентской базы. Веб-клиент для HTTP-обмена необязателен.

Расширение добавляет подсистему **Remote1C** с формами настройки и диагностики. Собственных справочников, документов, регистров и дополнительных таблиц бизнес-данных оно не создаёт, поэтому их реструктуризация для установки не нужна. Штатную проверку применимости и применение расширения всё равно выполните: дополнительные требования зависят от платформы и целевой конфигурации.

Настройки общие для базы и сохраняются через `ХранилищеСистемныхНастроек.СохранитьНастройкуПоУмолчанию`; читаются через `ЗагрузитьНастройкуПоУмолчанию`. Используются ключи `Remote1C.Nodes`, `Remote1C.LocalNode`, `Remote1C.Security`, `Remote1C.Diagnostics`, `Remote1C.RemoteProcedures`. Сохранение требует права «Сохранение данных пользователя».

## Быстрый старт

1. Установите `URC_Remote1C.cfe` в тестовую серверную и клиентскую базы через управление расширениями. Проверьте применимость, активность и новый сеанс.
2. Назначьте роль `URC_ОсновнаяРоль` отдельному пользователю HTTP-сервиса и добавьте необходимые права основной конфигурации на целевые данные. Роль расширения предоставляет Use всем 11 HTTP-методам.
3. Опубликуйте HTTP-сервис `URC_API` на веб-сервере. Корневой путь API: `/hs/remote1c/v1/`.
4. Откройте раздел **Remote1C → Remote1C: настройки узлов**. В серверной базе задайте уникальный «Код ServerNode» и отметьте «Разрешить входящие вызовы». Запись и процедуры сначала оставьте выключенными; сохраните настройки.
5. В той же форме клиентской базы добавьте строку подключения: код соединения `erp_my`, ожидаемый `Node`, URL публикации, пользователь и секрет. Отметьте «Активен»: `portable` и таймаут 60 секунд заполняются автоматически. Пустой режим означает `portable`. Сохраните настройки. Используйте HTTPS.
6. Выделите строку и нажмите «Проверить соединение», затем «Возможности». Откройте диагностику и выполните минимальный запрос. Подробные клики и разрешение записи/процедур описаны в разделе 5 руководства.

В `БазовыйURL` задаётся URL публикации, например `https://server.example.com/erp`. Суффикс `/hs/remote1c/v1/` клиент добавляет автоматически. Секрет вводится локально и в репозиторий не включается.

### Минимальный вызов из серверного BSL

После настройки подключения `erp_my`:

```bsl
Ping = URC_Клиент.Ping("erp_my");
Возможности = URC_Клиент.ПолучитьВозможности("erp_my");
Результат = URC_Клиент.ВыполнитьЗапросРасширенно(
    "erp_my", "ВЫБРАТЬ 1 КАК Значение");
Данные = Результат.Данные;
RequestId = Результат.RequestId;
```

Публичный API находится в `URC_Клиент`. Начальные вызовы принимают **ConnectionCode** — локальный код подключения. **Node** — стабильный идентификатор удалённой базы. Продолжающие вызовы получают маршрут из RemoteReference, RemoteValueStorage или RemoteObjectData; смешивать значения разных подключений нельзя.

Примеры чтения, записи и именованных процедур приведены в [руководстве](docs/developer-guide.md) и модуле `URC_ПримерыИспользования`. Демонстрационный код настройки адаптируйте перед запуском: он не является готовыми настройками вашей базы.

## Безопасность и ограничения

- Все операции выполняются с правами пользователя входящего HTTP-вызова; привилегированный режим расширение не включает.
- `РазрешитьRemote1C` управляет рабочими входящими вызовами. Успешный Ping и capability-флаг ещё не означают разрешения на операцию.
- Запись настраивается в принимающей базе через форму **Remote1C → Remote1C: настройки узлов**. Включите «Разрешить запись объектов». Для ограничения типов оставьте «Ограничивать запись списком типов» включённым и заполните «Разрешённые типы объектов», например `Справочник.Номенклатура; Документ.ЗаказКлиента`. Разделители — запятая или точка с запятой. Поле может быть пустым: при включённом ограничении это запрещает запись всем типам. Чтобы разрешить все типы, снимите ограничение списка; права пользователя HTTP-сервиса всё равно действуют. Нажмите «Сохранить».
- Процедуры требуют `AllowProcedureExecute` и разрешённой строки реестра. Произвольный текст BSL через HTTP не принимается.
- Запросы не имеют встроенной пагинации или ограничения строк; ограничивайте выборку и права пользователя.
- Таймаут клиента не гарантирует отмену серверной записи. Автоматического повтора POST и отдельного хранилища дедупликации RequestId нет.
- Настройки и секреты сохраняются в ХранилищеСистемныхНастроек базы. Отдельного шифрования поля секрета код не реализует. Штатный экспорт соединений исключает секрет, но URL и имя пользователя также проверяйте перед передачей.
