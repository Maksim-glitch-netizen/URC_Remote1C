# Руководство разработчика URC Remote1C

Версия расширения 0.5.0 • Протокол Remote1C/1.0 • 11 октября 2026

URC_Remote1C предназначено для синхронного взаимодействия информационных баз 1С через HTTP. Руководство объясняет установку, настройку, чтение и запись данных, именованные процедуры, диагностику и работу с исходниками. Начните с установки и проверки чтения, затем включайте только необходимые изменяющие операции.

Примеры используют демонстрационные URL, имена подключений и метаданные. Перед выполнением адаптируйте их к тестовой базе и проверьте права. Примеры с записью и процедурами выполняйте только на согласованных тестовых данных.

## 1. Что делает расширение и чего оно не делает

URC_Remote1C — самостоятельное расширение типа AddOn. Оно позволяет одной информационной базе 1С синхронно обратиться к другой опубликованной базе по HTTP, выполнить запрос на языке запросов 1С, прочитать реквизиты или снимок объекта, а для справочников и документов — создать, изменить и записать объект. Дополнительно клиент может вызвать заранее зарегистрированную серверную функцию по публичному имени и получить её результат.

### Поддерживаемые сценарии

- Проверка доступности узла (Ping) и чтение заявленных возможностей.
- Выполнение произвольного текста запроса на удалённом сервере с именованными параметрами.
- Получение переносимой ссылки RemoteReference из результата запроса.
- Чтение выбранных реквизитов объекта.
- Получение полного или выборочного снимка объекта вместе с табличными частями.
- Создание и изменение элементов справочников и документов.
- Запись документа, проведение и отмена проведения.
- Оптимистический контроль конфликтов: запись отклоняется, если изменяемые поля были изменены на сервере после чтения.
- Ленивое чтение обычных реквизитов типа ХранилищеЗначения через RemoteValueStorage и отдельный вызов получения содержимого.
- Вызов именованной процедуры из локального реестра сервера и чтение публичного списка процедур.
### Не поддерживается

- Передача и выполнение произвольного текста BSL по HTTP. Для вызова функции требуется заранее заданное соответствие публичного имени и локального обработчика в реестре сервера.
- Именованные заранее сохранённые запросы (NamedQuery=false).
- Удаление объектов и установка пометки удаления через объектный API.
- Запись объектов, кроме элементов справочников и документов.
- Постраничная выборка и автоматическое ограничение числа строк запроса.
- Передача RemoteEnum как параметра запроса.
- Передача ХранилищеЗначения напрямую в результате запроса не поддерживается. Для явной записи используйте RemoteValueStorageChange и объектный API из раздела 19.
## 2. Результаты полного анализа состава

Расширение не переопределяет и не перехватывает методы основной конфигурации. Это уменьшает риск конфликтов при обновлении, но работоспособность запросов и записи всё равно зависит от наличия целевых метаданных и прав пользователя HTTP-сервиса в конкретной базе.

| --- | --- |

Расширение использует управляемое приложение и русский вариант встроенного языка. Для используемых методов системного хранилища требуется платформа 8.3.26 или новее. Режим совместимости в метаданных — Version8_3_21; выгрузка этой поставки выполнена на 8.3.27.2214. Версия расширения 0.5.0, протокол Remote1C/1.0. Код принимает строковые версии семейства 1.x; поддержку отдельных функций проверяйте по capabilities и испытаниям совместимости в целевой базе.

## 3. Архитектура и жизненный цикл вызова

1. Код в базе-клиенте вызывает экспортную функцию URC_Клиент и передаёт ConnectionCode.
1. URC_Настройки получает параметры соединения: URL, пользователя, секрет, режим и таймаут.
1. URC_Клиент формирует транспортную Структуру с Protocol и RequestId; параметры и ссылки переводятся в переносимый формат.
1. URC_СериализацияXDTO преобразует структуру в JSON, а URC_HTTPКлиент отправляет Basic-auth HTTP-запрос.
1. HTTP-сервис удалённой базы передаёт запрос в URC_HTTPСервер. Сервер проверяет Content-Type, протокол и флаг РазрешитьRemote1C.
1. Операция выполняется с правами пользователя входящего HTTP-вызова. Привилегированный режим не включается.
1. Сервер возвращает Data, Execution, Status и тот же RequestId. Клиент проверяет протокол и совпадение RequestId.
Практический вывод: Remote1C не обходит RLS и права 1С. Сервисный пользователь должен иметь ровно те права чтения/записи, которые нужны интеграции.

## 4. Подготовка серверной и клиентской базы

### 4.1 Минимальные требования



| Компонент | Требование |
| --- | --- |
| Платформа 1С | 8.3.26 или новее: используются методы загрузки и сохранения настроек по умолчанию. Рабочая версия платформы проекта — 8.3.27.2214. |
| Конфигурация | Управляемое приложение, поддержка расширений; применимость заимствованного языка и метаданных проверяется в целевой базе. |
| Веб-сервер | Веб-публикация базы с HTTP-сервисом URC_API и веб-расширением, соответствующим используемой платформе 1С. |
| Сеть | Доступ от серверного процесса клиентской базы к URL публикации принимающей базы; для передачи учётных данных используйте HTTPS. |
| Пользователи | Отдельный пользователь HTTP-сервиса с ролью URC_ОсновнаяРоль и нужными прикладными правами; для настройки — право сохранения системных настроек. |


Для HTTP-обмена достаточно публикации HTTP-сервиса; пользоваться расширением через веб-клиент необязательно. Формы доступны в управляемом клиентском приложении. Расширение не задаёт универсального минимального номера версии Apache или IIS: поддержка веб-сервера, ОС и веб-клиента определяется требованиями выбранного релиза платформы 1С.

Для конфигураций, использующих файлы или ХранилищеЗначения, учитывайте объём передаваемых данных и ограничения веб-сервера. Требования к производительности определяются фактической нагрузкой интеграции, числом строк запросов и размером объектов.

### 4.2. Что должно быть установлено

- Расширение URC_Remote1C установлено и активно в обеих базах.
- HTTP-сервис URC_API опубликован в базе-сервере.
- Создан отдельный сервисный пользователь 1С; ему назначены права на HTTP-сервис и целевые данные.
- Между серверами открыт HTTP/HTTPS-доступ; для production предпочтителен HTTPS.
- Коды узлов уникальны и согласованы. На сервере локальный код должен совпадать с Node переносимых ссылок.
### 4.3. Публикация HTTP-сервиса

Корневой URL сервиса: remote1c. Внутренние шаблоны начинаются с /v1/. Клиент автоматически добавляет к БазовыйURL строку /hs/remote1c/v1/<операция>.


```bsl
БазовыйURL: https://server.example.com/erp
Итоговый Ping: https://server.example.com/erp/hs/remote1c/v1/ping
```

Не дублируйте путь: В поле БазовыйURL не добавляйте /hs/remote1c/v1. Если добавить его вручную, клиент сформирует неверный двойной путь.

### 4.4. Первичная настройка кодом


```bsl
// База-клиент
Соединение = URC_Настройки.НоваяНастройкаСоединения();
Соединение.Вставить("Node", "ERP_PROD");
Соединение.Вставить("БазовыйURL", "https://server.example.com/erp");
Соединение.Вставить("Активен", Истина);
Соединение.Вставить("РежимСериализации", "portable");
Соединение.Вставить("ТаймаутHTTP", 60);
Соединение.Вставить("Пользователь", "remote_user");
// Секрет введите локально через форму настройки; в исходниках его нет.
URC_Настройки.СохранитьСоединение("erp_my", Соединение);
// База-сервер
Локальные = URC_Настройки.ПолучитьЛокальныеНастройки();
Локальные.Вставить("КодУзла", "ERP_PROD");
URC_Настройки.СохранитьЛокальныеНастройки(Локальные);
Безопасность = URC_Настройки.ПолучитьНастройкиБезопасности();
Безопасность.Вставить("РазрешитьRemote1C", Истина);
Безопасность.Вставить("AllowObjectWrite", Ложь); // сначала только чтение
URC_Настройки.СохранитьНастройкиБезопасности(Безопасность);
```

## 5 Настройка через интерфейс без написания кода

### 5.1 Открытие настроек

После установки расширение добавляет подсистему «Remote1C» в командный интерфейс. Откройте этот раздел и команду «Remote1C: настройки узлов». Заголовок открытой формы — «Remote1C: настройки соединений». Здесь настраиваются исходящие подключения, локальный узел, входящие разрешения и реестр процедур. Команда «Remote1C: диагностика» открывает отдельную форму проверки.

Если раздел или команды не видны, проверьте активность и применимость расширения, назначение роли URC_ОсновнаяРоль и откройте новый сеанс. Расположение раздела зависит от командного интерфейса основной конфигурации. Для сохранения общих настроек необходимы административные права на системное хранилище.

### 5.2 Настройка принимающей базы

1. В группе «Локальный узел» заполните «Код ServerNode», например ERP_PROD. Это стабильный идентификатор этой базы. Он должен совпадать с Node в подключениях клиентов; задавайте разные коды разным базам.

2. Для чтения отметьте «Разрешить входящие вызовы». Оставьте «Разрешить запись объектов» и «Разрешить выполнение процедур» выключенными. «Ограничивать запись списком типов» оставьте включённым. При выключенной записи список «Разрешённые типы объектов» можно оставить пустым.

3. Нажмите «Сохранить». Затем проверьте опубликованный HTTP-сервис с клиентской стороны. Само включение флажка не публикует сервис и не назначает права пользователя.

### 5.3 Добавление исходящего подключения

1. В верхней таблице «Узлы» добавьте строку стандартной командой таблицы «Добавить» или клавишей Insert. Одна строка — одно удалённое подключение; отдельно создавать удалённый узел не требуется.

2. Заполните «Код соединения», например erp_my, и Node, например ERP_PROD. Код соединения — уникальный локальный ключ маршрута; Node — ожидаемый код принимающей базы. Для двух маршрутов к одной базе можно указать одинаковый Node, но разные коды соединения. Не дублируйте код соединения: при сохранении настройки собираются по этому ключу.

3. Задайте наименование, URL публикации без /hs/remote1c/v1, отметьте «Активен». В новой строке режим portable и таймаут 60 секунд заполняются автоматически. Поле режима можно оставить пустым: используется portable. При необходимости измените таймаут на положительное число секунд. Заполните пользователя HTTP-сервиса и секрет непосредственно в своей базе. Пример URL: https://server.example.com/erp.



| Поле | Тип / пример | Что означает |
| --- | --- | --- |
| Код соединения | Строка: erp_my | ConnectionCode — локальный ключ подключения, который принимают начальные вызовы URC_Клиент. |
| Node | Строка: ERP_PROD | Ожидаемый стабильный идентификатор удалённой базы; должен совпасть с ServerNode. |
| Наименование | Строка | Понятное человеку описание подключения. |
| URL | https://server.example.com/erp | URL публикации без /hs/remote1c/v1; расширение добавляет этот путь. |
| Активен | Булево | При Ложь обращение завершается CONNECTION_DISABLED. |
| Режим | portable | Заполняется автоматически. Пустое значение означает portable. native-xdto — экспериментальный alpha-режим. |
| Таймаут | Положительное число секунд | Новая настройка использует 60 секунд. Сохранение требует значения больше нуля. |
| Пользователь | Строка | Пользователь для аутентификации HTTP-соединения. |
| Секрет | Локально заданный пароль | Не включается в штатный экспорт соединений. Не храните реальные значения в репозитории. |


4. Нажмите «Сохранить», выделите созданную строку и выполните «Проверить соединение», затем «Возможности». Эти команды используют сохранённую настройку: перед проверкой изменения строки нужно сохранить. Проверяйте совпадение ServerNode с ожидаемым Node.

5. В чисто клиентской базе флажок «Разрешить входящие вызовы» можно оставить выключенным. Он нужен только тогда, когда эта база сама принимает рабочие HTTP-вызовы. Одна база может одновременно быть клиентом и сервером; настройте оба направления отдельно.

### 5.4 Разрешение записи объектов

Откройте принимающую базу под пользователем с доступом к форме Remote1C и правом «Сохранение данных пользователя». Перейдите в Remote1C → Remote1C: настройки узлов → группу «Локальный узел». Отметьте «Разрешить входящие вызовы» и «Разрешить запись объектов». Для ограничения типов оставьте «Ограничивать запись списком типов» включённым и заполните «Разрешённые типы объектов». Нажмите «Сохранить».

ObjectWriteAllowedMetadata — внутреннее имя настройки «Разрешённые типы объектов». Это список полных имён типов метаданных, а не имена пользователей, реквизитов или конкретных элементов. Используйте имя из Конфигуратора, например Справочник.Номенклатура или Документ.ЗаказКлиента. Название объекта в меню может отличаться от его имени метаданных. Примеры применимы только при наличии этих объектов в вашей конфигурации.

Вводите имена в одну строку, разделяя только запятой или точкой с запятой. Пробелы вокруг каждого имени допустимы. Пример: Справочник.Номенклатура; Документ.ЗаказКлиента. Альтернативный вариант: Справочник.Номенклатура, Документ.ЗаказКлиента. Звёздочка * и названия вида «Все» не являются разрешением всех типов.

Поле «Разрешённые типы объектов» может быть пустым. При включённом «Ограничивать запись списком типов» пустой список запрещает запись всем типам. При выключенном ограничении список, в том числе пустой, не применяется. Сам по себе пустой список не включает и не отключает запись.

Как разрешить запись всех типов

В принимающей базе включите «Разрешить входящие вызовы» и «Разрешить запись объектов», снимите «Ограничивать запись списком типов» и нажмите «Сохранить». Поле списка можно оставить пустым. Это снимает только ограничение расширения по типам объектов; права пользователя HTTP-сервиса на чтение, добавление, изменение, проведение и отмену проведения сохраняются.



| Разрешить запись объектов | Ограничивать запись списком типов | Результат |
| --- | --- | --- |
| Выключено | Любое значение | Объектная запись запрещена. |
| Включено | Включено, список заполнен | Разрешены только перечисленные типы при наличии прав пользователя. |
| Включено | Включено, список пуст | Объектная запись запрещена всем типам. |
| Включено | Выключено | По типам ограничений нет; действуют права пользователя и поддержка объектного API. |


Настройки расширения общие для принимающей базы и не назначаются отдельно каждому пользователю. Пользователь, сохраняющий эту форму, и пользователь входящего HTTP-вызова могут быть разными. Роль URC_ОсновнаяРоль открывает методы сервиса; необходимые права на объекты основной конфигурации назначаются сервисному пользователю отдельно. Настройка списка не выдаёт этих прав.

### 5.5 Регистрация именованной процедуры

В принимающей базе отметьте «Разрешить выполнение процедур». В таблице «Именованные процедуры» добавьте строку. В колонке «Обработчик внешней базы» укажите публичное имя, например Diagnostics.Echo.v1; в колонке «Внутренний обработчик» — точное имя экспортной серверной функции, например URC_ПримерыИспользования.ЭхоПроцедуры. Отметьте «Разрешена», заполните описание и сохраните настройки.

Колонка «Обработчик внешней базы» хранит имя, по которому клиент вызывает процедуру; это не адрес подключения. Внутренний обработчик должен существовать в серверной базе и принимать один контейнер параметров. Новую строку явно разрешайте только после проверки обработчика. Демонстрационный реестр при установке автоматически не добавляется. Подробности и примеры — в разделе 17.

### 5.6 Сохранение обновление импорт и экспорт

«Сохранить» записывает таблицу подключений, локальный код, политику безопасности и реестр процедур. Строки без кода соединения не становятся подключениями. Сначала проверяется корректность реестра и соединений; разные группы настроек записываются последовательно, поэтому сохранение не является одной общей транзакцией.

«Обновить» перечитывает сохранённые значения и заменяет текущие изменения формы. «Удалить узел» сразу удаляет выбранное сохранённое подключение из настроек базы и перечитывает форму. Перед этим сохраните необходимые изменения; удаление отдельной строковой командой таблицы применяется при общем сохранении.

«Экспорт без секретов» формирует XDTO JSON сохранённых подключений в группе «Импорт и экспорт». Поле секрета в штатный экспорт соединений не входит. Для переноса вставьте проверенный текст в поле «XDTO JSON» и нажмите «Импорт»: импорт сразу сохраняет подключения и перечитывает форму. Перед импортом сохраните необходимые изменения текущей формы. Проверьте результат и заполните секреты новых подключений отдельно. При импорте существующих подключений их секреты сохраняются. Локальный узел, политика безопасности и реестр процедур настраиваются отдельно.

### 5.7 Как настройки сохраняются в базе

Форма и BSL API используют один серверный модуль URC_Настройки и общие настройки информационной базы. Они не привязаны к пользователю, который открыл форму. Точные методы платформы: ХранилищеСистемныхНастроек.ЗагрузитьНастройкуПоУмолчанию(Ключ) и ХранилищеСистемныхНастроек.СохранитьНастройкуПоУмолчанию(Ключ, Настройки). Используются ключи Remote1C.Nodes, Remote1C.LocalNode, Remote1C.Security, Remote1C.Diagnostics и Remote1C.RemoteProcedures.

Эти методы доступны начиная с платформы 8.3.26; сохранение требует права «Сохранение данных пользователя». Код не включает привилегированный режим. ХранилищеСистемныхНастроек — механизм платформы: расширение не создаёт для настроек отдельные справочники, документы, регистры или собственные таблицы бизнес-данных. Отдельного шифрования поля секрета код расширения не реализует.

Установка расширения сама по себе не добавляет такие таблицы и не требует их реструктуризации. При этом проверка применимости и штатное применение изменений расширения обязательны; платформа или особенности целевой конфигурации могут потребовать дополнительной процедуры обновления. Наличие режима совместимости Version8_3_21 не означает, что используемые методы доступны на платформе 8.3.21.

## 6. Безопасность и права

### 6.1. Три независимых уровня допуска

1. HTTP-аутентификация: пользователь и секрет из узла передаются конструктору HTTPСоединение.
1. Права 1С: сервисный пользователь должен иметь Use для метода HTTP-сервиса и права на читаемые/изменяемые объекты.
1. Политика Remote1C: РазрешитьRemote1C, AllowObjectWrite, ObjectWriteStrictMode, ObjectWriteAllowedMetadata; для процедур отдельно действуют AllowProcedureExecute и признак Разрешена в строке локального реестра.
### 6.2. Рекомендуемая политика

- Используйте отдельного сервисного пользователя, не Администратора.
- Включайте РазрешитьRemote1C только после проверки HTTP-публикации и прав.
- Сначала оставьте AllowObjectWrite=Ложь и проверьте чтение.
- Для записи включайте ObjectWriteStrictMode=Истина и перечисляйте только необходимые метаданные.
- Не отключайте строгий режим в production: при Ложь разрешается запись любого поддерживаемого справочника/документа, доступного пользователю.
- Храните секреты ограниченно; экспорт формы намеренно не выгружает секреты.
- Используйте HTTPS: HTTP отправляет Basic credentials без транспортного шифрования.
- Оставляйте AllowProcedureExecute=Ложь до проверки зарегистрированных обработчиков. Разрешение записи объектного API не управляет выполнением процедур и не ограничивает код внутри обработчика.
## 7. Диагностика соединения

1. В форме настроек выберите строку узла и нажмите «Проверить соединение». Ожидайте Protocol=Remote1C/1.0 и Status=ok.
1. Нажмите «Возможности». Проверьте нужные ObjectGet/ObjectNew/ObjectWrite, SerializationModes и ProcedureExecute. Значение ProcedureExecute=Истина означает поддержку API, а не разрешение выполнения.
1. Откройте форму «Remote1C: диагностика», заполните ConnectionCode. После Ping форма показывает фактический ServerNode.
1. Выполните Ping, затем «Проверить XDTO», затем тестовый запрос ВЫБРАТЬ 1 КАК Значение.
1. Для процедур нажмите «Получить процедуры» в диагностике. Публичная таблица показывает Имя, Разрешена и Описание выбранного ConnectionCode; редактирование выполняется только в настройках серверной базы.
1. Скопируйте RequestId и найдите события Remote1C.* в журнале регистрации.


| Метрика | Смысл |
| --- | --- |
| Total, мс | Полное время клиентской операции. |
| Query, мс | Серверное выполнение запроса. |
| Attributes, мс | Чтение реквизитов. |
| Normalize, мс | Преобразование ссылок/перечислений и вложенных таблиц. |
| XDTO, мс | Сериализация и десериализация. |
| Строк | Количество строк верхнего уровня результата запроса. |
| ContentType | Тип исходного содержимого ХранилищаЗначения. |
| BinarySize | Размер исходных ДвоичныхДанных в байтах; иначе 0. |


## 8. Форматы данных и режимы сериализации

### 8.1. portable — основной режим по умолчанию

Скалярные значения сохраняются. Ссылки преобразуются в RemoteReference, перечисления — в RemoteEnum, таблицы значений и вложенные РезультатЗапроса — в переносимые ТаблицаЗначений. Этот режим безопаснее для разных конфигураций и понятнее при диагностике.



| RemoteReference | Тип / содержание |
| --- | --- |
| URCType | Строка "RemoteReference" |
| Node | Код базы-владельца ссылки |
| Metadata | Полное имя, например Справочник.Номенклатура |
| UUID | УникальныйИдентификатор ссылки |
| Presentation | Строковое представление |
| Empty | Булево: пустая ссылка или нет |




| RemoteEnum | Тип / содержание |
| --- | --- |
| URCType | Строка "RemoteEnum" |
| Node | Код базы-владельца |
| Metadata | Полное имя перечисления |
| ValueName | Имя значения перечисления |
| Presentation | Строковое представление |


### 8.2. native-xdto — экспериментальный alpha-режим

native-xdto — экспериментальный alpha-режим, сохранённый для совместимости. Для штатной настройки используйте portable. Ссылки и перечисления передаются как нативные значения 1С; вложенный РезультатЗапроса всё равно превращается в ТаблицаЗначений. Режим зависит от совместимости типов метаданных обеих баз. Для объектной записи расширение использует переносимый контейнер независимо от режима подключения. Именованные процедуры всегда используют portable.

Параметры запроса: Поддерживаются Строка, Число, Дата, Булево, УникальныйИдентификатор, Неопределено, Null, RemoteReference, а также вложенные Структура/Массив из этих типов. RemoteEnum как параметр запроса запрещён.

Для параметров процедур действуют отдельные правила: допускаются RemoteEnum, двоичные данные и таблицы значений внутри структуры. Ограничение RemoteEnum для параметров запроса сохраняется. Подробности и неподдерживаемые типы перечислены в разделе 17.

## 10. Как выполнять запросы

### 10.1. Минимальный пример


```bsl
ТекстЗапроса =
"ВЫБРАТЬ ПЕРВЫЕ 10
|    Ном.Ссылка КАК Ссылка,
|    Ном.Код КАК Код,
|    Ном.Наименование КАК Наименование
|ИЗ
|    Справочник.Номенклатура КАК Ном
|ГДЕ
|    НЕ Ном.ПометкаУдаления
|УПОРЯДОЧИТЬ ПО
|    Ном.Код";
Результат = URC_Клиент.ВыполнитьЗапрос("erp_my", ТекстЗапроса);
```

### 10.2. Параметризованный запрос


```bsl
Параметры = Новый Структура;
Параметры.Вставить("ДатаНачала", НачалоДня(ТекущаяДата()));
Параметры.Вставить("Организация", УдаленнаяОрганизация); // RemoteReference того же узла
ТекстЗапроса =
"ВЫБРАТЬ
|    Реал.Ссылка КАК Ссылка,
|    Реал.Номер КАК Номер,
|    Реал.Дата КАК Дата
|ИЗ
|    Документ.РеализацияТоваровУслуг КАК Реал
|ГДЕ
|    Реал.Дата >= &ДатаНачала
|    И Реал.Организация = &Организация";
Результат = URC_Клиент.ВыполнитьЗапрос(
    "erp_my", ТекстЗапроса, Параметры);
```

Псевдонимы: Не назначайте таблице псевдоним, совпадающий с именем поля. В запросах с несколькими источниками квалифицируйте каждое поле псевдонимом источника. Ошибки неоднозначности проявляются только при Запрос.Выполнить().

### 10.3. Вложенная табличная часть


```bsl
ТекстЗапроса =
"ВЫБРАТЬ
|    Реал.Ссылка КАК Ссылка,
|    Реал.Товары.(
|        Номенклатура,
|        Количество,
|        Цена) КАК Товары
|ИЗ
|    Документ.РеализацияТоваровУслуг КАК Реал";

Для Каждого СтрокаДокумента Из Данные Цикл
    Для Каждого СтрокаТовара Из СтрокаДокумента.Товары Цикл
        // СтрокаТовара.Номенклатура — RemoteReference в portable.
    КонецЦикла;
КонецЦикла;
```

### 10.4. Расширенный результат


```bsl
Опции = Новый Структура("Timeout,SerializationMode", 30, "portable");
Ответ = URC_Клиент.ВыполнитьЗапросРасширенно(
    "erp_my", "ВЫБРАТЬ 1 КАК Значение", Неопределено, Опции);
Данные = Ответ.Данные;
RequestId = Ответ.RequestId;
Количество = Ответ.КоличествоСтрок;
TotalMs = Ответ.ДлительностьМС;
QueryMs = Ответ.QueryMs;

XDTOMs = Ответ.XDTOMs;
```

### Правила для новичка

- Всегда ограничивайте выборку ПЕРВЫЕ, периодом или другим отбором; сервер не добавляет лимит автоматически.
- Используйте параметры &Имя вместо конкатенации значений в текст запроса.
- Имя параметра — ключ структуры Параметры без символа &.
- RemoteReference-параметр должен иметь тот же Node и ConnectionCode, что и выбранное соединение; иначе возвращается REMOTE_CONNECTION_MISMATCH. Значение без ConnectionCode отклоняется с REMOTE_CONNECTION_REQUIRED.
- Результат всегда выгружается целиком в ТаблицаЗначений; большие выборки потребляют память на сервере и клиенте.
- Неподдерживаемый тип колонки приводит к UNSUPPORTED_RESULT_TYPE; выбирайте простые значения, ссылки и перечисления.
- ХранилищеЗначения не поддерживается в результатах ВыполнитьЗапрос и ВыполнитьЗапросРасширенно; используйте объектные методы и отдельное чтение хранилища.
## 11. Как получать реквизиты и данные объектов

### 11.1. Найти RemoteReference


```bsl
Отбор = Новый Структура;
Отбор.Вставить("Дата", ДатаДокумента);
Отбор.Вставить("Организация", УдаленнаяОрганизация);
Отбор.Вставить("ПометкаУдаления", Ложь);
Ссылка = URC_Клиент.НайтиУдаленнуюСсылку(
    "erp_my",
    "Документ.РеализацияТоваровУслуг",
    "Номер",
    НомерДокумента,
    Отбор);
```

ПолноеИмяМетаданных должно состоять ровно из категории и имени. Допускаются Справочник, Документ, ПланСчетов, ПланВидовХарактеристик, ПланВидовРасчета, ПланОбмена, БизнесПроцесс, Задача. Имена реквизитов проходят строгую проверку. Отборы — только равенство. Если найдено 0 строк, возвращается Неопределено; если больше одной — исключение REMOTE_REFERENCE_NOT_UNIQUE (формируется клиентской логикой поиска).

### 11.2. Только реквизиты


```bsl
Реквизиты = URC_Клиент.ПолучитьРеквизиты(
    Ссылка,
    "Код,Наименование,Артикул");
Сообщить(Реквизиты.Наименование);
```

ИменаРеквизитов: Неопределено — все доступные; строка через запятую; Массив или ФиксированныйМассив. ВерсияДанных исключена, Ссылка возвращается отдельным полем. Точки и пробелы в прямом имени запрещены.

### 11.3. Полный или выборочный снимок


```bsl
// Все реквизиты и все табличные части
Данные = URC_Клиент.ПолучитьДанныеОбъекта(Ссылка);
// Только шапка
Опции = Новый Структура("ТабличныеЧасти", Ложь);
Шапка = URC_Клиент.ПолучитьДанныеОбъекта(Ссылка, Опции);
// Выборочно
Опции = Новый Структура;
Опции.Вставить("Реквизиты", "Номер,Дата,Организация");
ТЧ = Новый Структура;
ТЧ.Вставить("Товары", "Номенклатура,Количество,Цена");
Опции.Вставить("ТабличныеЧасти", ТЧ);
Данные = URC_Клиент.ПолучитьДанныеОбъекта(Ссылка, Опции);
```



| ТабличныеЧасти | Поведение |
| --- | --- |
| Неопределено / ключ отсутствует | Прочитать все табличные части и все колонки. |
| Ложь | Не читать ни одной табличной части. |
| Структура | Прочитать только перечисленные табличные части. |
| Значение ключа Неопределено | Все колонки указанной табличной части. |
| Строка / Массив | Только указанные колонки; имена проверяются по метаданным. |


### 11.4. Ленивое чтение ХранилищаЗначения

ПолучитьРеквизиты, ПолучитьДанныеОбъекта и ПолучитьОбъект не раскрывают содержимое обычного реквизита типа ХранилищеЗначения. Вместо содержимого возвращается RemoteValueStorage; чтение выполняется только явным вызовом.


```bsl
Реквизиты = URC_Клиент.ПолучитьРеквизиты(
    Ссылка, "ПрисоединенныйФайл");
Хранилище = Реквизиты.ПрисоединенныйФайл;
Если URC_Клиент.ЭтоУдаленноеХранилище(Хранилище) Тогда
    Содержимое = URC_Клиент.ПолучитьЗначениеХранилища(Хранилище);
КонецЕсли;
```

RemoteValueStorage содержит URCType, ЭтоХранилище, Node, ConnectionCode, Metadata, Reference и Location. Для Location=Attribute передаётся Attribute. Для Location=TablePart передаются TablePart, Column, RowNumber (нумерация с нуля), DataVersion и, в редактируемом снимке, RowId. Отсутствующее Location трактуется как Attribute для обратной совместимости.

- Перед вызовом клиент проверяет capability ValueStorageGet. Старый сервер возвращает FEATURE_NOT_SUPPORTED.
- ДвоичныеДанные передаются как RemoteBinaryData: URCType, Encoding=base64, Size и Data. Клиент проверяет размер и возвращает ДвоичныеДанные.
- Структуры, массивы и ТаблицаЗначений внутри содержимого обрабатываются рекурсивно; вложенное ХранилищеЗначения отклоняется VALUE_STORAGE_CONTENT_UNSUPPORTED.
- ХранилищеЗначения в табличных частях поддерживается через RemoteValueStorage и явные изменения из раздела 19; учитывайте служебную колонку URC__RowId.
## 12. Как изменять и создавать объекты

### 12.1. Изменить существующий элемент справочника


```bsl
Объект = URC_Клиент.ПолучитьОбъект(УдаленнаяНоменклатура);
Объект.Реквизиты.Наименование = "Новое наименование";
Результат = URC_Клиент.Записать(Объект);
```

### 12.2. Создать новый элемент


```bsl
Объект = URC_Клиент.СоздатьОбъект(
    "erp_my", "Справочник.Номенклатура");
Объект.Реквизиты.Наименование = "Новый товар";
Объект.Реквизиты.Артикул = "NEW-001";
Результат = URC_Клиент.Записать(Объект);
```

### 12.3. Изменить табличную часть


```bsl
Документ = URC_Клиент.ПолучитьОбъект(УдаленныйДокумент);
Товары = Документ.ТабличныеЧасти.Товары; // ТаблицаЗначений
НоваяСтрока = Товары.Добавить();
НоваяСтрока.Номенклатура = УдаленнаяНоменклатура; // тот же Node
НоваяСтрока.Количество = 2;
НоваяСтрока.Цена = 100;
Результат = URC_Клиент.Записать(Документ, "Запись");
```

Важное поведение: Изменённая табличная часть заменяется целиком методом Загрузить. Не отправляйте частичную таблицу как «дельту»: отсутствующие строки будут удалены из табличной части объекта.

### 12.4. Контейнер RemoteObjectData



| Блок | Содержание |
| --- | --- |
| Реквизиты | Редактируемые реквизиты объекта в переносимом виде. |
| ТабличныеЧасти | Структура ИмяТЧ → ТаблицаЗначений. |
| СлужебныеДанные.URCType | Всегда "RemoteObjectData". |
| СлужебныеДанные.Node | Узел-владелец; подмена запрещена. |
| СлужебныеДанные.Metadata | Полное имя метаданных. |
| СлужебныеДанные.Reference | RemoteReference существующего объекта. |
| СлужебныеДанные.IsNew | Признак нового объекта. |
| OriginalAttributes / OriginalTableParts | Глубокий исходный снимок для расчёта дельты и конфликта. |
| LoadedAt | Дата/время чтения снимка. |


### 12.5. Что нельзя менять

Запись обычных реквизитов выполняется прежним способом. ХранилищеЗначения изменяется только через RemoteValueStorageChange: Set, Clear или Copy. Прямая подмена дескриптора отклоняется с VALUE_STORAGE_CHANGE_REQUIRED; код VALUE_STORAGE_WRITE_NOT_SUPPORTED сохранён в таблице совместимости для старых узлов, но корректная запись версии 0.5.0 его не возвращает.

### 12.6. Защита от конфликтов

Перед записью сервер блокирует ссылку и сравнивает только те реквизиты и табличные части, которые клиент изменил, с исходным снимком. Если на сервере значение уже изменилось, операция отклоняется OBJECT_CONFLICT (HTTP 409). Перечитайте объект, повторно внесите изменение и только затем записывайте.

## 13. Как записывать, проводить и отменять проведение документов



| Режим API | Алиасы | Действие 1С |
| --- | --- | --- |
| write | Запись / write | Объект.Записать(РежимЗаписиДокумента.Запись) |
| post | Проведение / post | Объект.Записать(РежимЗаписиДокумента.Проведение) |
| unpost | ОтменаПроведения / unpost | Объект.Записать(РежимЗаписиДокумента.ОтменаПроведения) |


### 13.1. Записать без проведения


```bsl
Документ = URC_Клиент.ПолучитьОбъект(УдаленныйДокумент);
Документ.Реквизиты.Комментарий = "Изменено через Remote1C";
Ответ = URC_Клиент.Записать(Документ, "Запись");
```

### 13.2. Провести


```bsl
Документ = URC_Клиент.ПолучитьОбъект(УдаленныйДокумент);
Документ.Реквизиты.Комментарий = "Проведено через Remote1C";
Ответ = URC_Клиент.Записать(Документ, "Проведение");
```

### 13.3. Отменить проведение


```bsl
Документ = URC_Клиент.ПолучитьОбъект(УдаленныйДокумент);
Ответ = URC_Клиент.Записать(Документ, "ОтменаПроведения");
```

Запись, проведение и отмена проведения выполняются штатным методом документа внутри транзакции. Поэтому срабатывают проверки заполнения, ПередЗаписью, ОбработкаПроведения, движения регистров и другие механизмы конкретной конфигурации. Ошибка прикладной логики возвращается как OBJECT_WRITE_ERROR или OBJECT_VALIDATION_ERROR.

Не путайте: Поле Проведен нельзя изменять напрямую. Чтобы изменить состояние проведения, передайте РежимЗаписи функции URC_Клиент.Записать.

### 15.3. Журнал регистрации

Фильтр события: Remote1C.*. В комментарии пишутся RequestId, Direction, Node, User, Operation, Mode, метрики времени и количества строк/реквизитов, Metadata, UUID, IsNew, режим и результат записи. Для Remote1C.ValueStorageGet дополнительно фиксируются Attribute, ContentType и BinarySize; содержимое и Base64 никогда не журналируются. Специальные события: Remote1C.Security.Denied, Remote1C.ObjectConflict, Remote1C.Transport.Error, Remote1C.Logging.Error. Для именованных процедур используется Remote1C.ProcedureExecute: дополнительно пишется публичное имя Procedure, без полного набора параметров и результата. Серверная ошибка обработчика имеет отдельное событие Remote1C.ProcedureExecute.Detail с RequestId, внутренним именем обработчика и технической цепочкой ошибки; ограничьте доступ к этому журналу.

Диагностика инцидента: Всегда фиксируйте RequestId из исключения или расширенного ответа. Он связывает исходящий вызов клиента и входящую обработку сервера.

| Высокий | HTTP Basic credentials без HTTPS могут быть перехвачены. Для production используйте HTTPS. |
| Средний | Нет лимита строк и пагинации; неограниченный запрос может перегрузить память/время сервера. |
| Средний | Изменение табличной части заменяет её целиком. Неполная таблица удалит отсутствующие строки. |
| Средний | native-xdto зависит от совместимости метаданных и типов между базами; portable безопаснее. |
| Средний | Настройки хранятся в системном хранилище. Экспорт скрывает секрет, но код не реализует отдельное шифрование секрета. |
| Средний | RemoteBinaryData передаётся как Base64 и увеличивает размер HTTP-тела; большие файлы читайте только по явной необходимости и учитывайте память обеих баз. |
| Высокий | Разрешённый обработчик может изменять данные с правами HTTP-пользователя. AllowObjectWrite, строгий список Metadata и контроль конфликтов объектного API автоматически к его внутреннему коду не применяются. |


## 17 Именованные удалённые процедуры

Используйте именованную процедуру, когда на сервере нужна заранее разработанная прикладная операция. Клиент передаёт публичное имя и контейнер параметров. Сервер находит имя в собственном реестре, проверяет разрешения и один раз вызывает соответствующую экспортную функцию. Текст BSL и внутренний путь к функции не являются параметрами клиентского API.

### Подготовка серверной базы

1. Установите доработку в клиентскую и серверную базы. В возможностях сервера должен присутствовать ProcedureExecute=Истина. При отсутствии возможности клиент завершит вызов FEATURE_NOT_SUPPORTED до отправки нового POST.
1. Назначьте сервисному пользователю роль URC_ОсновнаяРоль: она предоставляет Use всем 11 HTTP-методам URC_API, включая ProcedureExecute.POST и Procedures.GET. Добавьте необходимые прикладные права основной конфигурации и опубликуйте сервис.
1. В серверной базе откройте «Remote1C: настройки узлов», раздел «Именованные процедуры». Оставьте «Разрешить выполнение процедур» выключенным до проверки реестра.
1. Добавьте строку: Имя = Diagnostics.Echo.v1; Обработчик = URC_ПримерыИспользования.ЭхоПроцедуры; Разрешена = Ложь; Описание = Диагностическое эхо параметров. Нажмите «Сохранить», затем «Обновить» и проверьте сохранённые значения.
1. Для тестового вызова включите Разрешена у нужной строки и «Разрешить выполнение процедур», затем сохраните. Должен быть включён также РазрешитьRemote1C. После проверки выключите диагностическую строку, если постоянный доступ не нужен.
Реестр хранится локально в ХранилищеСистемныхНастроек под именем настройки RemoteProcedures. Он не входит в экспорт и импорт соединений. Новая строка выключена по умолчанию; установка расширения не регистрирует и не включает примеры автоматически. Перед редактированием обеспечьте администратору права чтения и сохранения системных настроек.

### Публичное имя и обработчик

Поле Имя непустое и состоит только из латинских букв A–Z/a–z, цифр, точки, дефиса и подчёркивания. Пробелы и кириллица запрещены. Имена уникальны без учёта регистра; поиск также не учитывает регистр. Версию прикладного контракта удобно включать в имя, например Sales.FillOrder.v1.

Поле Обработчик задаётся строго как Модуль.Функция: два идентификатора, разделённых одной точкой, без скобок, пробелов и выражений. Разрешены русские и латинские буквы, цифры после первого символа и подчёркивание. Общий модуль должен существовать, выполняться на сервере, быть неглобальным и непривилегированным. Функция должна быть экспортной и принимать один параметр. Проверки повторяются непосредственно перед вызовом; существование и экспорт самой функции окончательно проверяются платформой при выполнении.

Готовый диагностический обработчик уже находится в URC_ПримерыИспользования:


```bsl
Функция ЭхоПроцедуры(Параметры) Экспорт
    Возврат Параметры;
КонецФункции
```

При отсутствии Parameters обработчик получает Неопределено. Одна только регистрация имени не создаёт прикладную функцию: Sales.FillOrder.v1 в примерах является условным контрактом, для которого нужно отдельно реализовать и зарегистрировать свой обработчик.

### Вызов из клиентского кода

В примерах erp_my — ConnectionCode настроенного соединения, ERP_PROD — ожидаемый Node серверной базы. Для списка достаточно разрешённого входящего Remote1C; общий запрет выполнения процедур не запрещает чтение списка.


```bsl
Список = URC_Клиент.ПолучитьПроцедуры("erp_my");
// Каждый элемент: Имя, Разрешена, Описание. Обработчик не передаётся.
Параметры = Новый Структура("Текст,Число", "Remote1C", 10);
Настройки = Новый Структура("Timeout", 60);
Ответ = URC_Клиент.ВыполнитьПроцедуру(
    "erp_my", "Diagnostics.Echo.v1", Параметры, Настройки);
// Ответ.Текст = "Remote1C", Ответ.Число = 10.
БезПараметров = URC_Клиент.ВыполнитьПроцедуру(
    "erp_my", "Diagnostics.Echo.v1");
// БезПараметров = Неопределено.
```

ВыполнитьПроцедуру возвращает непосредственно результат обработчика, без транспортной обёртки Data/Execution. ПолучитьПроцедуры возвращает массив структур. Значение Разрешена в публичном списке учитывает и флаг строки, и AllowProcedureExecute: при общем запрете все строки отображаются выключенными.

### Типы параметров и результата

Верхний уровень Параметры — Структура, ФиксированнаяСтруктура или Неопределено. Внутри допускаются Строка, Число, Дата, Булево, УникальныйИдентификатор, Null, Неопределено, вложенные структуры, массивы, фиксированные массивы, таблицы значений, RemoteReference, RemoteEnum, ДвоичныеДанные и RemoteBinaryData. Таблицу или массив верхнего уровня поместите в поле структуры.

Контейнеры обходятся рекурсивно. Фиксированные структуры и массивы переносятся как обычные изменяемые контейнеры. У таблиц сохраняются имена и заголовки колонок, строки и значения; исходная типизация колонок не переносится. Не передавайте РезультатЗапроса: сначала получите ТаблицаЗначений.

До POST клиент проверяет Node и ConnectionCode всех вложенных RemoteReference и RemoteEnum. Отсутствующий ConnectionCode даёт REMOTE_CONNECTION_REQUIRED, несовпадение — REMOTE_CONNECTION_MISMATCH. Не подменяйте эти поля: получите значение через нужное соединение. На сервере ссылки и перечисления восстанавливаются в нативные значения; в результате клиент получает portable-дескрипторы с исходным ConnectionCode.

Двоичные данные передаются через RemoteBinaryData/Base64, на сервере и у клиента в результате восстанавливаются в ДвоичныеДанные. RemoteBinaryData не получает ConnectionCode. Учитывайте рост размера HTTP-тела при передаче файлов.

ХранилищеЗначения, RemoteValueStorage, RemoteObjectData, РезультатЗапроса и произвольные объекты не входят в контракт процедур. Для неподдерживаемых параметров возвращается UNSUPPORTED_PARAMETER_TYPE, для результата — PROCEDURE_RESULT_UNSUPPORTED. Нативную ссылку клиентской базы нельзя использовать вместо RemoteReference серверной базы.

### Готовые примеры в расширении

Все следующие функции находятся в общем модуле URC_ПримерыИспользования. Клиентские примеры используют Diagnostics.Echo.v1 и требуют описанной выше регистрации на сервере. Функции возвращают результат, чтобы вызывающий код мог его проверить.

- ПодготовитьПримерРеестраПроцедур() возвращает копию текущего реестра и при отсутствии имени добавляет выключенную диагностическую строку. Настройки не сохраняет и существующее правило не перезаписывает. Просмотрите результат перед явным вызовом СохранитьХранимыеПроцедуры.
- ПримерСпискаПроцедур(ConnectionCode) получает публичный список; ПримерПроцедурыБезПараметров(ConnectionCode) демонстрирует результат Неопределено.
- ПримерПроцедурыСоСтруктурой(ConnectionCode) передаёт структуру с массивом и Timeout; ПримерПроцедурыСТаблицей(ConnectionCode) передаёт таблицу внутри поля Строки.
- ПримерПроцедурыСДвоичнымиДанными(ConnectionCode, Данные) принимает уже подготовленные ДвоичныеДанные и возвращает структуру с полем Данные.
- ПримерПроцедурыСУдаленнымиЗначениями(ConnectionCode, УдаленнаяСсылка, УдаленноеПеречисление) демонстрирует передачу RemoteReference и необязательного RemoteEnum из того же соединения.
- ПримерВызоваИменованнойПроцедуры(ConnectionCode, УдаленныйЗаказ) показывает вызов отдельно реализуемого Sales.FillOrder.v1. Он не является тестом готового обработчика.
### Контракт HTTP и диагностика

POST /hs/remote1c/v1/procedure/execute принимает Protocol, RequestId, Procedure и необязательный Parameters. Ответ содержит общий статус, Data с результатом и Execution с ElapsedMs, ServerNode и Procedure. GET /hs/remote1c/v1/procedures возвращает публичный массив в Data. Формат JSON формируется URC_СериализацияXDTO; Options.SerializationMode не переводит эти операции в native-xdto.

Коды отказов и HTTP-статусы добавлены в раздел 15. При диагностике сначала проверяйте общий входящий доступ и AllowProcedureExecute, затем наличие имени, признак строки и корректность обработчика. Подробное имя обработчика и техническая ошибка находятся только в серверном журнале. Основное событие Remote1C.ProcedureExecute связывается с вызовом по RequestId; полные параметры и результат в нём не записываются.

### Транзакции и повторные вызовы

Диспетчер не открывает общую транзакцию, не включает привилегированный режим и не повторяет обработчик. Он выполняет одну зарегистрированную функцию с правами пользователя HTTP-вызова. Собственные проверки бизнес-доступа, транзакцию, валидацию и идемпотентность при необходимости реализует автор обработчика. Флаги AllowObjectWrite и ObjectWriteAllowedMetadata относятся к объектному API и не ограничивают произвольные действия разрешённой функции.

Таймаут на клиенте не гарантирует отмену серверной операции. Ошибка преобразования результата также может возникнуть после записи данных обработчиком. Не повторяйте изменяющий вызов вслепую; определите результат по журналу и прикладным данным. RequestId служит корреляции и сам по себе не обеспечивает защиту от повторного выполнения.

### Проверка перед эксплуатацией

На тестовой базе проверьте выключенный общий флаг, неизвестное имя, выключенную строку, неэкспортную функцию и исключение внутри функции. Затем выполните эхо без параметров, со структурой, таблицей, двоичными данными и удалёнными значениями. Проверьте отказ при чужом ConnectionCode и неподдерживаемом типе; подтвердите, что в публичном списке нет Обработчик, а в основном журнале нет полного содержимого параметров.

Разделение PROCEDURE_HANDLER_INVALID и PROCEDURE_EXECUTION_ERROR зависит от цепочки ошибки платформы; подтвердите оба случая на используемой версии 1С. Если профиль безопасности запрещает динамическое выполнение, согласуйте доступность этого механизма с администратором. Для процедуры, меняющей данные, отдельно проверьте поведение при таймауте и отсутствие повторного выполнения.

## 18 Проверка обмена на тестовом стенде

Проверяйте расширение в двух тестовых базах через реальную публикацию. В комплект поставки входят формы диагностики и BSL-примеры. Отдельная внешняя обработка интеграционных тестов в этот репозиторий не включена. Примеры ниже задают ожидаемые результаты проверки и сами по себе не являются протоколом успешно выполненных тестов.

### Подготовка стенда

Установите одинаковую версию расширения в обе базы, создайте отдельного пользователя HTTP-сервиса и настройте HTTPS. Для клиента используйте ConnectionCode test_connection, для сервера задайте уникальный Node TEST_SERVER. Имена ниже примерные; проверяйте наличие нужных метаданных в своей конфигурации.

Оставьте AllowObjectWrite и AllowProcedureExecute выключенными до проверки чтения. Для последующих изменяющих проверок используйте только согласованные тестовые объекты и заранее подготовьте резервную копию.



| Проверка | Ожидаемый результат |
| --- | --- |
| Самопроверка XDTO | Кнопка проверки XDTO в форме диагностики завершает локальное преобразование успешно. |
| Ping | Status=ok, совместимый Protocol; ServerNode совпадает с ожидаемым Node. |
| Capabilities | ExtensionVersion и SerializationModes согласованы; нужные capability-флаги присутствуют. |
| Минимальный запрос | ВЫБРАТЬ 1 КАК Значение возвращает одну строку с числом 1; сохранён RequestId. |
| Чтение объекта | Найденная RemoteReference имеет Node и ConnectionCode; доступны выбранные реквизиты. |
| Чужое подключение | Смешение переносимых значений разных подключений отклоняется до отправки. |
| Именованная процедура | Неизвестное или выключенное имя отклоняется; согласованная диагностическая процедура возвращает ожидаемое значение. |
| Запись | При выключенном флаге получен отказ; после разрешения только нужного типа изменение тестового объекта перечитано. |
| Конфликт | Конкурентное изменение между чтением и записью вызывает OBJECT_CONFLICT, без молчаливого перезаписывания. |
| ХранилищеЗначения | После Set, Clear или Copy перечитаны целевые данные; перестановка строк сохраняет адресацию URC__RowId. |


### Минимальная проверка чтения


```bsl
Ping = URC_Клиент.Ping("test_connection");
Возможности = URC_Клиент.ПолучитьВозможности("test_connection");
Ответ = URC_Клиент.ВыполнитьЗапросРасширенно(
    "test_connection", "ВЫБРАТЬ 1 КАК Значение");
```

Проверьте Ответ.Данные, Ответ.КоличествоСтрок и Ответ.RequestId. Затем сопоставьте вызов с журналом регистрации обеих баз. Если предпосылка не выполнена, отметьте проверку как «не выполнялась» и сначала исправьте причину.

### Проверка записи и восстановление

Сохраните исходные значения тестового объекта, выполните ровно одно согласованное изменение, перечитайте результат и восстановите исходное значение отдельной проверяемой операцией. При неудачном восстановлении остановите проверки и проверьте объект вручную. Проведение документа может иметь прикладные последствия; простой обратной записи реквизита недостаточно для отката движений.

При транспортном таймауте не отправляйте изменяющий POST автоматически повторно. По RequestId и фактическим данным выясните, выполнилась ли серверная операция. RequestId служит корреляции; отдельное хранилище защиты от повторного выполнения в расширении не реализовано.

## 19. Запись ХранилищеЗначения

### 19.1. Назначение и совместимость

Версия 0.5.0 сохраняет ленивое чтение содержимого и добавляет явную запись ХранилищеЗначения в реквизитах объекта и ячейках табличных частей. Протокол остаётся Remote1C/1.0; новые клиенты определяют поддержку по capability-флагам ValueStorageWrite, TablePartValueStorage и ValueStorageServerCopy.

### 19.2. Публичный API URC_Клиент



| Метод | Назначение |
| --- | --- |
| ПолучитьЗначениеХранилища(Дескриптор) | Лениво получает portable-содержимое. |
| ИзменитьЗначениеХранилища(Base, Значение) | Формирует Set для существующего реквизита или ячейки. |
| НовоеЗначениеХранилища(Значение) | Формирует Set без Base для нового объекта или новой строки. |
| ОчиститьЗначениеХранилища(Base) | Формирует Clear; после записи хранится пустое значение. |
| СкопироватьЗначениеХранилища(Base, Source) | Копирует исходное ХранилищеЗначения на сервере без распаковки. |


Содержимое Set может быть скаляром, ссылкой или перечислением Remote1C, структурой, массивом, таблицей значений либо двоичными данными RemoteBinaryData. Вложенные RemoteValueStorage и RemoteValueStorageChange запрещены. Base и Source должны относиться к тому же Node и ConnectionCode.

### 19.3. Реквизит объекта


```bsl
Данные = URC_Клиент.ПолучитьОбъект(УдаленнаяСсылка);
Base = Данные.Реквизиты.ФайлХранилище;
Данные.Реквизиты.ФайлХранилище = URC_Клиент.ИзменитьЗначениеХранилища(Base, НовоеСодержимое);
Результат = URC_Клиент.Записать(Данные);
```

Для очистки вместо Set присвойте результат ОчиститьЗначениеХранилища(Base). Для нового объекта присвойте НовоеЗначениеХранилища(Значение): Base у новой цели отсутствует.

### 19.4. Табличные части и URC__RowId

Если редактируемая табличная часть содержит хотя бы одну колонку ХранилищеЗначения, снимок включает транспортную колонку URC__RowId. У существующих строк это уникальный UUID, у новых строк — пустая строка. Колонку нельзя удалять или менять; неизвестные и повторные значения отклоняются. Если прикладные метаданные уже содержат реквизит URC__RowId, объект не выдаётся для редактирования и возвращается REMOTE_OBJECT_SERVICE_COLUMN_CONFLICT.


```bsl
ТаблицаТЧ = Данные.ТабличныеЧасти.Вложения;
СтрокаТЧ = ТаблицаТЧ[0];
Base = СтрокаТЧ.ДанныеФайла;
СтрокаТЧ.ДанныеФайла = URC_Клиент.ИзменитьЗначениеХранилища(Base, НовыеДанные);
URC_Клиент.Записать(Данные);
```

RowNumber в дескрипторе нумеруется с нуля и относится к моменту чтения. DataVersion защищает ленивое чтение от использования устаревшего адреса. При записи сервер связывает строки по URC__RowId, поэтому перестановка строк не перенаправляет изменение в другую ячейку. Полная табличная часть реконструируется один раз; неизменённые ХранилищеЗначения переносятся из текущих серверных строк без вызова Получить().

### 19.5. Copy без передачи содержимого


```bsl
Base = Данные.Реквизиты.Приемник;
Source = ДругиеДанные.Реквизиты.Источник;
Данные.Реквизиты.Приемник = URC_Клиент.СкопироватьЗначениеХранилища(Base, Source);
URC_Клиент.Записать(Данные);
```

Copy читает исходное ХранилищеЗначения только как контейнер и присваивает его цели без Получить() и без Base64 в HTTP-запросе. Для дескриптора ячейки Source дополнительно проверяется DataVersion.

### 19.6. Конфликты, ошибки и журнал



| Код | HTTP | Причина |
| --- | --- | --- |
| VALUE_STORAGE_CHANGE_REQUIRED | 422 | Хранилище изменено без явного Set/Clear/Copy. |
| VALUE_STORAGE_CHANGE_INVALID | 422 | Повреждена операция или нарушен контракт полей. |
| VALUE_STORAGE_TARGET_MISMATCH | 422 | Base не совпадает с исходной целью. |
| VALUE_STORAGE_STALE_DESCRIPTOR | 409 | DataVersion или RowNumber дескриптора устарели. |
| VALUE_STORAGE_ROW_ID_INVALID | 422 | URC__RowId отсутствует, повторяется или неизвестен. |
| REMOTE_OBJECT_SERVICE_COLUMN_CONFLICT | 422 | Имя URC__RowId занято прикладным реквизитом. |


Set, Clear и запись табличной части используют консервативную проверку ВерсияДанных и при конкурентном изменении возвращают OBJECT_CONFLICT (409). Журнал содержит только адрес цели, тип операции в агрегированных счётчиках и размеры; Value, Base64 и распакованное содержимое не записываются.

### 19.7. Проверочный список

- Проверить capability-флаги перед использованием записи.
- Хранить исходный Base из того же снимка и не собирать дескриптор вручную.
- Не удалять URC__RowId из редактируемой таблицы; для новой строки оставлять пустую строку.
- Обрабатывать 409 как необходимость повторно получить объект или дескриптор.
- Не журналировать содержимое, Base64, Value, Base и Source целиком.
## 20 Как устроен обмен

Remote1C выполняет синхронные HTTP-вызовы. У расширения нет очереди сообщений, фонового расписания, плана обмена и автоматического сопоставления справочников. Прикладной код выбирает момент вызова, ConnectionCode, текст запроса или имя операции и самостоятельно использует полученные данные.

### Последовательность запроса

1. URC_Клиент читает локальную настройку соединения и ожидаемый Node. Начальные вызовы принимают ConnectionCode; продолжение работы со ссылкой или объектом получает его из переносимого значения.

2. Параметры переводятся в portable-представление, проверяются вложенные Node и ConnectionCode. Формируется структура с Protocol и новым UUID RequestId.

3. URC_СериализацияXDTO записывает структуру в XDTO JSON. URC_HTTPКлиент добавляет /hs/remote1c/v1 к URL публикации, создаёт соединение с указанными пользователем, секретом и таймаутом.

4. Платформа и веб-сервер аутентифицируют пользователя. URC_API передаёт вызов в URC_HTTPСервер. Для POST проверяются Content-Type, протокол, RequestId и РазрешитьRemote1C; для записи и процедур действуют дополнительные разрешения.

5. Запрос выполняется под правами пользователя входящего HTTP-вызова. Объектная запись использует прикладные методы целевой конфигурации; процедуру разрешает локальный реестр.

6. Ответ содержит Status, RequestId, ServerNode, Data и, для рабочих POST, Execution. Клиент проверяет контракт и ожидаемый Node, рекурсивно привязывает ConnectionCode и возвращает прикладные данные.

7. В журнал записываются направление, идентификатор вызова, результат и длительности. Бизнес-логика клиента определяет дальнейшее действие и обработку ошибок.

### Идентификаторы и повторы

Node характеризует базу, ConnectionCode — локальный маршрут к ней. Два подключения могут иметь одинаковый Node и разные URL, но переключение после ошибки выполняет прикладной код. Сервер не использует входящий ConnectionCode как разрешение доступа или команду маршрутизации.

GET ping и capabilities не проверяют РазрешитьRemote1C в прикладном обработчике, поэтому успешный Ping подтверждает доступность, но не допуск к чтению, записи или процедурам. Capabilities объявляет реализованные возможности, а не выдаёт права.

Таймаут HTTP ограничивает ожидание клиента и не доказывает отмену работы сервера. Автоматического повторения POST нет. Прикладная идемпотентность и восстановление после неопределённого результата — ответственность конкретной интеграции.

### Точное тело HTTP

Приведённые в разделе 14 структуры показывают логический контракт. Не заменяйте XDTO JSON обычным JSON без проверки типизации UUID, даты, структуры и таблицы значений. Для внешнего клиента получите образец тела через URC_СериализацияXDTO.СериализоватьВJSON и проверьте обратное преобразование. URL-параметры не заменяют структуру POST.



| Метод и путь после /hs/remote1c | Операция |
| --- | --- |
| GET /v1/ping | Доступность и ServerNode. |
| GET /v1/capabilities | Версии и поддержка функций. |
| POST /v1/query | Текст запроса и именованные параметры. |
| POST /v1/attributes | Выбранные реквизиты. |
| POST /v1/object-data | Снимок объекта для чтения. |
| POST /v1/object/get | Контейнер для контролируемого изменения. |
| POST /v1/object/new | Новый контейнер справочника или документа. |

### Начало разработки

Изучайте публичный API в URC_Клиент, версии и пути в URC_Протокол, нормализацию типов в URC_ПортативныеТипы. При изменении HTTP-операции одновременно проверьте обработчик URC_API, серверную реализацию, клиента, capabilities, карту ошибок, роль и документацию.

### Цикл изменения

1. Опишите требование, затрагиваемые объекты и ожидаемый результат; сделайте резервную копию. 2. Получите свежий baseline из DEV. 3. Измените только планируемые файлы. 4. Проверьте BSL, XML и ссылки, затем diff. 5. Загрузите изменённые объекты именно в расширение. 6. Примените изменение расширения и откройте новый сеанс. 7. Выполните проверки раздела 18 и прикладного сценария. 8. Снова выгрузите XML и CFE из одной проверенной базы; проверьте комплект поставки.

Для именованной процедуры создайте экспортную серверную функцию, принимающую один контейнер параметров. Зарегистрируйте публичное имя и точный обработчик локально на сервере. Протестируйте типы, разрешения, исключения и побочные действия; не передавайте произвольное имя обработчика через HTTP.

Отсутствие пользовательских запросов к новой базе в протоколе проверки нельзя заменять проверкой в другой базе. Успешный статический анализ BSL не подтверждает выполнение запроса и права пользователя.

## 22 Установка обновление и выпуск

### Установка и проверка

Сделайте резервную копию тестовой базы. В Конфигураторе откройте управление расширениями и загрузите URC_Remote1C.cfe как расширение с этим именем. При обновлении выберите существующее расширение. Проверьте сообщения применимости и активность; завершите применение и откройте новый сеанс. Исходники основной конфигурации этим способом не заменяются.

Назначьте пользователям необходимые роли и прикладные права, опубликуйте HTTP-сервис URC_API средствами своей среды, затем задайте настройки серверного узла и подключения клиента. Не угадывайте URL публикации по имени базы. После каждого обновления выполните Ping, capabilities, минимальный запрос и сценарии изменённых функций.

### Варианты выгрузки для платформы 8.3.27

Пути и сервер в следующих командах являются заполнителями. Подставьте свои значения и заранее создайте каталоги. Windows-аутентификация должна быть настроена; не записывайте пароль в команду или журнал.

  /DumpConfigToFiles "<каталог-src>"

Это одна командная строка; переносы показаны только для читаемости. Для первой выгрузки используйте новый каталог. Инкрементальный -update применяйте только к корректной предыдущей выгрузке того же расширения с ConfigDumpInfo.xml. После завершения проверьте код процесса, значение DumpResult, журнал и наличие ожидаемых файлов.

При необходимости восстановите предыдущую версию расширения через управление расширениями и перепроверьте применимость и запуск. Это откатывает код расширения; уже выполненные бизнес-изменения не отменяются. Их восстановление планируется отдельно по резервной копии и прикладным процедурам.

## 23 Настройки и конфиденциальные данные

### Где хранятся настройки

URC_Настройки использует общие для базы настройки: ХранилищеСистемныхНастроек.ЗагрузитьНастройкуПоУмолчанию(Ключ) и ХранилищеСистемныхНастроек.СохранитьНастройкуПоУмолчанию(Ключ, Настройки). Ключи: Remote1C.Nodes, Remote1C.LocalNode, Remote1C.Security, Remote1C.Diagnostics и Remote1C.RemoteProcedures. Методы доступны с платформы 8.3.26. Сохранение требует права «Сохранение данных пользователя» и выполняется без привилегированного режима. Права на изменение настроек и права HTTP-пользователя на данные проверяются отдельно.

Секрет соединения хранится в настройке базы, а не в XML исходников. В коде расширения нет отдельного механизма шифрования этого поля. Ограничьте права на настройки и резервные копии базы; используйте отдельного пользователя и HTTPS. Реальные секреты вводите только в своей среде.

Штатный экспорт соединений не содержит Секрет, но содержит URL и Пользователь. Эти значения тоже могут быть внутренними: перед публикацией замените их демонстрационными. При импорте существующий секрет сохраняется; новому подключению он задаётся отдельно. Импортируйте только проверенный файл: название «без секретов» не является проверкой произвольного внешнего содержимого.

Реестр процедур и политика безопасности не входят в экспорт соединений. Установка расширения не включает диагностические процедуры автоматически. Демонстрационные значения remote_user и password в модуле примеров не являются рабочими реквизитами; заменяйте их локально и не запускайте пример настройки без адаптации.

### Подготовка публичного репозитория

Публикуйте src, README.md, docs/developer-guide.md, руководство и CFE одного выпуска. Не включайте конфигурации окружения, .env, приватные ключи, выгрузки всей базы, журналы с полезной нагрузкой, локальные резервные копии, архивы технических заданий и историю другого каталога.

Проверяйте видимые файлы, свойства DOCX, содержимое ZIP и распакованный CFE. Если публикуется существующий Git-репозиторий, отдельно проверьте все ветки, теги и историю: удаление файла из рабочей копии и .gitignore не удаляют старые коммиты. Для нового репозитория можно импортировать только проверенный комплект файлов без прежней .git.

Сохраняйте исходники и документацию с нейтральными свойствами автора и редактора. Не добавляйте вымышленные имена разработчиков. В отчёте проверки секретов фиксируйте путь, номер строки и тип находки, без самого значения. При подтверждённом попадании действующего секрета в историю сначала замените его в своей среде.

## 24 Практические ограничения и эксплуатация

### Права и нагрузка

Роль URC_ОсновнаяРоль предоставляет Use всем 11 HTTP-методам URC_API, включая вызов и список именованных процедур. Назначьте её сервисному пользователю вместе с необходимыми правами основной конфигурации. Флаги входящих операций, список разрешённых типов записи и реестр процедур проверяются дополнительно. Для работы сервиса не требуются полные административные права.

Сервис query принимает произвольный текст запроса, доступный пользователю 1С. Отдельного allowlist текста, ограничения строк и пагинации в этой версии нет. Ограничивайте выборку в прикладном запросе и не используйте HTTP-пользователя с избыточными правами.

Проведение и запись запускают прикладную логику целевой конфигурации. AllowObjectWrite и список типов управляют объектным API, но не ограничивают действия зарегистрированного обработчика процедуры. Ответственность за валидацию параметров и транзакции внутри такого обработчика лежит на его разработчике.

Крупные таблицы и файлы увеличивают память клиента, сервера и HTTP-тело; Base64 увеличивает размер двоичных данных. Согласуйте лимиты веб-сервера и таймауты. HTTP-клиент содержит простой разбор URL хоста, порта и пути; особые адреса, IPv6, query-параметры публикации и нестандартную аутентификацию проверяйте отдельно.

### Разбор инцидента

Сначала сохраните RequestId, ConnectionCode, ожидаемый и фактический Node, операцию, время и код ошибки. Сопоставьте события Remote1C.* на обеих сторонах. Проверьте публикацию, сертификат, права HTTP-метода, настройки Security, строку реестра процедуры и фактическое состояние объекта. Не прикладывайте секрет, Base64 файла и полный снимок данных к публичному issue.

После изменения прав, публикации или расширения открывайте новый сеанс и повторяйте минимальную проверку. Для OBJECT_CONFLICT перечитайте объект и заново рассчитайте изменение; не отключайте контроль конфликта как способ исправления.

## Приложение B. Типовой обработчик ошибок


```bsl
Попытка
    Ответ = URC_Клиент.ВыполнитьЗапросРасширенно(
        "erp_my", ТекстЗапроса, Параметры);
Исключение
    ТекстОшибки = ОписаниеОшибки();
    ЗаписьЖурналаРегистрации(
        "MyIntegration.Remote1C.Error",
        УровеньЖурналаРегистрации.Ошибка,
        Неопределено,
        Неопределено,
        ТекстОшибки);
    ВызватьИсключение;
КонецПопытки;
```

Не скрывайте исходное исключение без регистрации. Для безопасного чтения допустим ограниченный повтор после анализа причины CONNECTION_ERROR или TRANSPORT_TIMEOUT. Для процедуры таймаут или разрыв после отправки не доказывает, что сервер не выполнил действие. Автоматически повторять такой POST нельзя: сначала установите результат по RequestId и данным сервера. Идемпотентность при необходимости обеспечивает прикладной обработчик. Для OBJECT_CONFLICT повтор без перечитывания объекта запрещён.

## Приложение E Node и ConnectionCode

Node — стабильный идентификатор информационной базы. ConnectionCode — локальный код конкретной настройки подключения. Несколько ConnectionCode могут указывать на один Node; один ConnectionCode всегда содержит ровно один Node.

### Правила клиентского API

- Ping, ПолучитьВозможности, ВыполнитьЗапрос, ВыполнитьЗапросРасширенно, НайтиУдаленнуюСсылку, СоздатьОбъект, ВыполнитьПроцедуру и ПолучитьПроцедуры принимают ConnectionCode.
- ПолучитьРеквизиты, ПолучитьДанныеОбъекта, ПолучитьОбъект, ПолучитьЗначениеХранилища и Записать извлекают ConnectionCode только из переносимого значения.
- После каждого ответа клиент сравнивает настроенный Node с Execution.ServerNode или ServerNode. Несовпадение приводит к CONNECTION_NODE_MISMATCH.
- Клиент рекурсивно добавляет ConnectionCode в RemoteReference, RemoteEnum, RemoteValueStorage и RemoteObjectData. RemoteBinaryData остаётся без ConnectionCode.
- Удалённые значения из разных Node или ConnectionCode нельзя смешивать в параметрах запроса, процедуры и при записи объекта. Проверка вложенных значений выполняется до отправки POST.
### Миграция настроек

При первом чтении настройки формата 0.3.0 мигрируют идемпотентно: прежний ключ КодУзла X становится ConnectionCode X, а поле Node получает X. URL, пользователь и секрет сохраняются. Экспорт и импорт содержат отдельные ConnectionCode и Node; секрет никогда не экспортируется и сохраняется при импорте существующего соединения.

### Контрактные ошибки



| Код | Назначение |
| --- | --- |
| CONNECTION_NOT_FOUND | ConnectionCode отсутствует в локальных настройках. |
| CONNECTION_DISABLED | Настройка соединения отключена. |
| CONNECTION_NODE_MISMATCH | Ответ получен не от ожидаемого Node. |
| REMOTE_CONNECTION_REQUIRED | В продолженном удалённом значении отсутствует ConnectionCode. |
| REMOTE_CONNECTION_MISMATCH | Смешаны значения разных Node или ConnectionCode. |
